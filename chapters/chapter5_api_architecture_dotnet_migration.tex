\chapter{Architecture Blueprint: Clean Architecture and Database Schemas}

\begin{tcolorbox}[storybox, title={The Architectural Evolution in Brief}]
As Quizard expands to support millions of concurrent participants across telco partner portals (bKash, Banglalink, Robi), the backend is undergoing an architectural upgrade: transitioning from the original Django monolithic codebase to a high-throughput **.NET 10 Clean Architecture** backed by an enterprise **PostgreSQL** cluster.
\end{tcolorbox}

\section{Critical PostgreSQL Table Schemas and Indexing}
To sustain high concurrency during live 60-question tournaments, the PostgreSQL database utilizes optimized multi-column indexes:

\begin{lstlisting}[language=sql, caption={Essential PostgreSQL Indexes for Sub-Millisecond Queries}]
-- Index for live daily leaderboard lookups
CREATE INDEX idx_quizplay_event_date_valid 
ON quizapp_quizplaysummery (event_id, portal_id, date, is_valid, right_count DESC, time_taken ASC);

-- Index for player attempt history and anti-memorization lookups
CREATE INDEX idx_quizplay_msisdn_date 
ON quizapp_quizplaysummery (msisdn, date);

-- Index for weekly tournament consolidation stored procedures
CREATE INDEX idx_quizplay_weekly_range 
ON quizapp_quizplaysummery (event_id, date, is_valid) 
INCLUDE (msisdn, right_count, time_taken, user_id, portal_id);
\end{lstlisting}

\begin{tcolorbox}[summarybox, title={Chapter Key Takeaways}]
\begin{itemize}
    \item .NET 10 Clean Architecture isolates domain business rules from external frameworks and persistence details.
    \item In-memory mock stores (\texttt{ScoreStore}) have been completely eliminated in favor of direct, verified PostgreSQL database transactions.
    \item Composite indexing on \texttt{(event\_id, portal\_id, date, is\_valid)} guarantees sub-millisecond query latency even during peak concurrent tournament traffic.
\end{itemize}
\end{tcolorbox}
